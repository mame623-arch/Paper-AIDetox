# 개인 논문 기록 아카이브 설계

작성일 2026-09-09

시안: `https://claude.ai/code/artifact/90dbe86c-3b41-4d44-8c33-a7b8bd68d72e`
(시안의 "쌓인 기록" 차트는 논문과 문장을 한 막대에 쌓아 그렸으나 아래에서 바꿨다)

## 배경

멤버 페이지는 지금 논문이 평평하게 나열되는 목록이다. 주간 보고서 작업으로
`highlights.purpose`(수집 용도)와 `papers.category` / `published_year` 가 생겼지만,
읽는 곳이 차시별 보고서뿐이라 **한 사람의 기록을 전 기간에 걸쳐 보는 화면이 없다.**

이 스펙은 멤버 페이지를 개인 아카이브로 바꾼다. 주간 보고서가 *한 차시 × 전원*을
자른다면, 이쪽은 *한 사람 × 전 기간*을 자른다.

## 범위

**포함**

- 멤버 페이지를 `기록` / `읽기 경향` 두 탭으로 개편
- `기록` 탭 — 논문별 수집 문장, 용도 필터, 페이지네이션, 집계 레일(차트 4종)
- `읽기 경향` 탭 — 준비중 placeholder
- 멤버 기준 수집 문장 조회
- 집계 계산 (순수 함수)
- 과거 논문의 arXiv 메타데이터 백필

**제외**

- **노드 그래프 뷰, 임베딩, LLM 분석.** 검토 내용은
  `docs/superpowers/notes/2026-09-09-graph-view.md` 에 남겼다. `읽기 경향` 탭이
  그것들이 붙을 자리다.
- 스키마 변경 — 이번 작업은 컬럼을 하나도 더하지 않는다. 주간 보고서 작업이 만든
  것만으로 충분하다.

## 지금 화면에서 반드시 살아남는 것

아카이브는 **덧붙이는 것**이지 갈아엎는 것이 아니다. 지금 멤버 페이지에 있는 아래
기능은 하나도 사라지지 않는다. 특히 앞의 두 개는 다른 화면이 의존한다.

| 기능 | 왜 필수인가 |
| --- | --- |
| 논문 **편집**(제목·저자·PDF 링크) | PDF 링크가 없는 논문의 뷰어 화면이 "멤버 페이지에서 **편집**으로 PDF 링크를 넣어 주세요"라고 안내한다 (`app/members/[id]/papers/[paperId]/page.tsx:149-152`). 편집이 사라지면 그 복구 경로가 끊긴다 |
| **읽을 예정** 목록과 상태 전환 | `읽을 예정 → 읽음` 을 바꿀 수 있는 곳이 여기뿐이다. 등록은 차시 쪽으로 옮겼지만 상태 전환은 옮기지 않았다 |
| 논문 **삭제** | 다른 곳에 없다 |
| **한줄평** 작성·수정·삭제 | 지금 논문 줄마다 `useSessionReview` 로 붙어 있다 (`app/members/[id]/page.tsx:283`) |
| 논문 **검색**(제목·저자) | 기록이 쌓일수록 더 필요해진다 |

**`읽은 논문만 아카이브에 온다`는 결정은 유지하되, `읽을 예정`은 별도 섹션으로 남긴다.**
아카이브 본문(문장이 붙는 곳)과 집계는 읽은 논문만 다루고, 읽을 예정은 그 아래에
간단한 목록으로 둔다 — 기록이 아니라 할 일이므로 문장도 차트도 붙지 않는다.

## 화면

### 탭

`기록` / `읽기 경향` 둘. **URL 로 구분한다** (`/members/[id]?tab=trend`) — 링크로
공유되고 뒤로 가기가 동작한다. 기본은 `기록`.

탭 밖 머리에는 아바타·이름과 한 줄 요약이 온다:
`읽은 논문 4편 · 수집 문장 17개 · 한줄평 3차시 · 4차시 참석`.

각 수치의 정의:

| 항목 | 정의 |
| --- | --- |
| 읽은 논문 | `status === "read"` 인 논문 수. 읽을 예정은 세지 않는다 |
| 수집 문장 | `purpose` 가 빈 값이 아닌 하이라이트 수 (소유 규칙은 아래 조회 절) |
| 한줄평 | `fetchReviewsByMember` 가 돌려주는 행 수 |
| 참석 차시 | **`fetchMemberSessionIds` 를 쓴다** (`lib/db.ts`). 논문 등록 ∪ 출석 행에서 불참 선언을 뺀 집합이라, 직접 세면 "논문 없이 참석"을 놓치거나 불참을 잘못 포함한다 |

### `기록` 탭 — 본문

**본문의 단위는 논문이다.** 수집 문장을 따로 모으지 않고 각 논문 카드 아래에 그
논문에서 나온 문장을 붙인다.

```
[용도] 전체 17  좋은 표현 7  문단 구조 4  논리 연결 5  기타 1
[검색] 제목·저자

┌ RETHINKING MACHINE UNLEARNING FOR LARGE LANGUAGE MODELS  [읽음] [예정][편집][✕]
│ Sijia Liu 외 · 2026.09.03 · 논문 디톡스 7차시 · 기계학습 · 2024년 · 문장 6
│ 한줄평  LLM unlearning 서베이부터 읽어봤는데…              [✓ 한줄평]
├──────────────────────────────────────────────────────────────
│ “Unlearning is not forgetting: …”
│ 정의를 한 문장으로 가르는 방식이 좋았다.
│ [좋은 표현]
└
                        ← 1 2 →

── 읽을 예정 ──
┌ Some Upcoming Paper                        [읽을 예정] [읽음][편집][✕]
```

- **아카이브 본문은 읽은 논문만.** 읽을 예정은 아래 별도 섹션에 제목·메타·조작만.
- 논문 제목은 PDF 하이라이터로 가는 링크다 (`/members/[id]/papers/[paperId]`).
- 메타 줄은 저자 · 읽은 날짜 · 차시 · 분야 · 발행연도 · 문장 수. 분야·연도·읽은 날짜가
  비어 있으면 그 항목만 생략한다.
- **한줄평은 지금처럼 논문 줄에 붙는다** — `useSessionReview` 를 그대로 쓴다. 차시
  단위라 같은 차시 논문이 여럿이면 같은 글이 붙고, 본인이면 작성·수정·삭제가 된다.
- **상태 전환·편집·삭제 버튼은 본인 페이지에서 그대로 보인다** (`canEdit` 규칙 유지).
- 문장이 없는 논문은 `수집한 문장이 없습니다.` 로 접힌다. 감추지 않는다 —
  읽었다는 사실 자체가 기록이다.
- **논문 정렬은 `read_date` 내림차순**, 같으면 `created_at` 내림차순. `read_date` 가
  없는 읽은 논문은 맨 뒤로 보낸다.

**용도 필터** — 칩을 누르면 그 용도의 문장만 남고, **그 용도의 문장이 하나도 없는
논문은 목록에서 빠진다.** (필터를 걸어도 논문을 남기면, 페이지를 넘겼을 때 "이 용도로
수집한 문장이 없습니다"만 가득한 쪽이 나온다.) 필터가 꺼져 있을 때는 문장이 없는
논문도 전부 보인다.

**용도 칩의 구성** — 프리셋 셋(`좋은 표현`·`문단 구조`·`논리 연결`)은 각각 칩이 되고,
**그 밖의 모든 자유 입력값은 `기타` 하나로 묶는다.** `PurposeSelect` 는 사용자가 친
문자열을 그대로 `purpose` 에 저장하므로(`components/PurposeSelect.tsx:56-66`) 값의
가짓수에 상한이 없다 — 값마다 칩을 만들면 칩 줄이 무한정 길어진다. 다만 **문장에
붙는 라벨에는 실제 입력값을 그대로 보여준다** (`기타` 가 아니라 `발표자료용`).

**페이지네이션** — 논문 단위로 한 쪽에 10편. 필터가 걸려 있으면 **걸러진 뒤의 목록을**
페이지로 나눈다. URL 에 담는다 (`?page=2`).

**검색** — 지금 있는 제목·저자 검색을 유지한다. 검색과 용도 필터는 함께 걸리고,
페이지는 둘 다 적용한 뒤의 목록 기준이다.

### `기록` 탭 — 집계 레일

오른쪽 레일에 차트 넷. **모두 단일 색조(앱의 `--accent`)** 이고 정체는 라벨이 나른다 —
범주별 색을 쓰지 않는다. **집계 대상은 읽은 논문과 그 논문의 수집 문장뿐이다.**
읽을 예정 논문은 어느 차트에도 들어가지 않는다.

| 차트 | 형태 | 세는 단위 |
| --- | --- | --- |
| 쌓인 문장 | 월별 세로 막대 | **문장 수.** 한 측정만 그린다 |
| 분야 | 가로 막대 | **논문 수** (`papers.category`, `categoryLabel` 로 이름 변환) |
| 발행연도 | 가로 막대 | **논문 수** (`papers.published_year`) |
| 용도 | 가로 막대 | **문장 수** (`highlights.purpose`, 프리셋 3 + 기타) |

- **월별 막대에 논문 수를 같이 쌓지 않는다.** 시안에서는 논문과 문장을 한 칸에
  쌓아 그렸는데, 두 값의 자릿수가 다르다 — 월 논문 1~2편 대 월 문장 10~40개.
  쌓으면 논문 칸이 실오라기가 되어 읽히지 않고, 축 하나에 단위가 다른 두 측정을
  얹는 셈이 된다. 월별 논문 수는 낮은 수라 머리의 요약 줄과 아래 목록이 이미 답한다.
- **월별 축은 읽은 날짜(`read_date`) 기준**이고 **최근 12개월만** 그린다. 상한이 없으면
  2년 치가 쌓였을 때 좁은 레일에 막대 24개가 들어간다. 차트 제목에 기준을 적는다.
- **`read_date` 가 없는 논문의 문장은 월별 차트에서 뺀다.** 스키마상
  `status='read'` 와 `read_date=null` 이 동시에 가능하다(`supabase/schema.sql`).
  어느 달에 넣을 근거가 없으므로 넣지 않는다. 그 논문은 목록에도, 분야·연도·용도
  차트에도 정상적으로 들어간다 — 빠지는 것은 월별 차트뿐이다.
- 값이 없는 항목(분야 미상, 연도 미상)은 **막대에서 뺀다.** 별도 "미상" 막대를 만들지
  않는다 — 백필로 채워질 값이라 영구적인 범주가 아니다.
- 데이터가 적으면 성기게 보이는 것을 받아들인다. 억지로 채우지 않는다.
- 차트 라이브러리를 쓰지 않는다. CSS 와 인라인 SVG 로 그린다.

### `읽기 경향` 탭

준비중 placeholder. 무엇이 올 자리인지 한 문단으로 적고, 그 이상 만들지 않는다.
가짜 데이터나 스켈레톤 애니메이션을 넣지 않는다 — 준비중인 것은 준비중으로 보이는
편이 정직하다.

### URL 상태

- `?tab=` 은 `record`(기본) 또는 `trend`. 모르는 값은 `record` 로 본다
- `?page=` 는 1 이상의 정수. 숫자가 아니거나 1 미만이면 1, 마지막 쪽을 넘으면
  마지막 쪽으로 맞춘다
- **탭을 바꾸면 `page` 를 버린다.** 다른 탭의 쪽 번호를 들고 갈 이유가 없다
- **용도 필터나 검색어를 바꾸면 1쪽으로 돌아간다.** 목록이 달라졌는데 3쪽에 머무르면
  빈 화면이 된다
- 삭제·상태 전환으로 현재 쪽이 비면 마지막 쪽으로 물러난다

### 남의 아카이브

**남의 페이지도 같은 화면이 그대로 보인다.** 집계도 문장도 다 보인다.
편집 권한만 지금 규칙 그대로다 — 논문 편집·삭제·상태 전환과 한줄평 작성은 본인만.

## 데이터

### 조회

`lib/db.ts` 에 하나 추가한다. 나머지는 이미 있다
(`fetchMember`, `fetchPapersByMember`, `fetchSessions`, `fetchReviewsByMember`,
`fetchMemberSessionIds`).

```ts
/**
 * 그 사람이 수집한 문장 — purpose 가 붙은 하이라이트만.
 * 논문마다 따로 조회하지 않고 논문 id 를 모아 한 번에 읽는다
 * (fetchSessionHighlights 의 멤버 버전).
 */
fetchHighlightsByMember(memberId: string): Promise<Highlight[]>
```

**누구의 문장인가 — 두 조건을 모두 만족해야 한다.**

1. `papers.added_by === memberId` 인 논문에 달려 있고,
2. `highlights.member_id` 가 그 멤버이거나 **비어 있다**

조건 1만 쓰면 남의 문장이 섞일 수 있다. 지금은 논문 주인만 하이라이트를 남길 수
있지만(`418427e`), 그 제한이 생기기 전 데이터에는 남의 논문에 단 하이라이트가 있을 수
있고 DB(RLS)는 그것을 막지 않는다. 조건 2의 "비어 있다"는 사이드바에서 이름을 고르지
않고 남긴 옛 기록을 살리기 위한 것이다 — 그 논문의 주인 것으로 본다.

`fetchSessionHighlights` 와 같은 방식으로, 마이그레이션 전이면 경고만 남기고 `[]` 를
돌려준다.

### 집계

`lib/archive.ts` — 순수 함수. 화면과 떨어져 있어야 테스트할 수 있다.

```ts
interface ArchiveStats {
  /** 최근 12개월, 시간 오름차순. 기록이 없는 달도 0 으로 채운다 */
  monthly: { month: string; highlights: number }[];
  /** 논문 수. 개수 내림차순, 동률이면 code 오름차순. 빈 code 제외 */
  categories: { code: string; count: number }[];
  /** 논문 수. 연도 내림차순. null 제외 */
  years: { year: number; count: number }[];
  /** 문장 수. 개수 내림차순, 동률이면 이름 오름차순. 기타는 하나로 묶음 */
  purposes: { purpose: string; count: number }[];
}

/** papers 는 **읽은 논문만** 넘긴다. 거르는 것은 호출부의 책임이다. */
buildArchiveStats(readPapers: Paper[], highlights: Highlight[]): ArchiveStats
```

**정렬은 필드마다 다르다.** 하나의 규칙으로 뭉뚱그리지 않는다 — `monthly` 는 시간순,
`years` 는 연도순, `categories` 와 `purposes` 는 개수순이다. 동률 처리까지 정해야
테스트가 결정적이다.

- `monthly` 는 **최근 12개월** 창을 만들고 그 안에서 기록이 없는 달도 0 으로 채운다.
  비어 있는 달이 사라지면 추이가 왜곡된다. 창의 끝은 오늘이 속한 달이다.
- 문장은 **소속 논문의 `read_date`** 로 센다. 하이라이트의 `created_at` 을 쓰지
  않는다 — 나중에 태그를 달면 엉뚱한 달로 간다. `read_date` 가 없으면 월별에서 뺀다.
- `purposes` 는 프리셋(`좋은 표현`·`문단 구조`·`논리 연결`) 외의 모든 값을 `기타` 로
  합산한다. 판정은 `lib/highlightPurposes.ts` 의 `isPreset` 을 쓴다.

문장을 논문별로 묶는 것도 여기 둔다.

```ts
groupHighlightsByPaper(highlights: Highlight[]): Map<string, Highlight[]>
```

### 백필

`scripts/backfill-arxiv.mjs` — 주간 보고서 스펙에서 미뤄둔 것. 이제 읽는 곳이 생겼다.

**실행 방법**

```bash
npm run build && npx next start -p 3200 &      # /api/arxiv 를 띄운다
BASE=http://localhost:3200 node scripts/backfill-arxiv.mjs
```

- `BASE` 는 실행 중인 앱의 주소. 기본값 `http://localhost:3000`
- Supabase 주소·키는 `.env.local` 또는 환경변수(`NEXT_PUBLIC_SUPABASE_URL`,
  `NEXT_PUBLIC_SUPABASE_ANON_KEY`)에서 읽는다. 이 저장소의 RLS 는 anon 키로 쓰기를
  허용하므로 별도 서비스 키가 필요 없다
- 파싱 코드를 두 벌로 갈라놓지 않으려고 앱의 `/api/arxiv` 를 부른다. 그래서 앱이
  떠 있어야 한다

**무엇을 채우나** — `pdf_url` 이 arXiv 인 논문 중 `category` **또는**
`published_year` 가 빈 것. **필드마다 따로 판단한다.** 한쪽만 비어 있어도 그 필드를
채운다 — "둘 다 비었을 때만" 으로 하면 부분적으로 빈 행이 영영 안 채워진다.
이미 값이 있는 필드는 덮어쓰지 않는다.

- 몇 번을 다시 돌려도 안전하다
- arXiv 요청 사이에 간격을 둔다 (arXiv API 권고)
- 실패한 논문은 건너뛰고 목록으로 보고한다. 중간에 멈추지 않는다
- **공유 DB 에 쓰므로 사용자 승인을 받고 실행한다**

백필 없이도 화면은 돈다. 분야·연도 막대가 비어 있을 뿐이다.

## 에러 처리

- **수집 문장 조회 실패** — 경고만 남기고 빈 목록. 논문 목록과 나머지 집계는 그대로 돈다
- **분야·연도가 빈 논문** — 메타 줄에서 그 항목만 생략하고, 차트 막대에서 뺀다
- **읽은 논문이 하나도 없는 멤버** — 본문은 `아직 읽은 논문이 없습니다.` 레일은 빈
  차트를 그리지 않고 `기록이 쌓이면 여기에 보입니다.` 로 대체한다
- **필터 결과가 비면** — `이 용도로 수집한 문장이 없습니다.` 페이지네이션은 감춘다

## 검증

- `npx tsc --noEmit`, `npm run lint`, `npm run build`, `npm test`
- `buildArchiveStats` 와 `groupHighlightsByPaper` 는 단위 테스트로 덮는다 —
  12개월 창과 빈 달 채우기, `read_date` 없는 논문 제외, 값 없는 항목 제외,
  필드별 정렬과 동률, 기타 합산, 세는 단위(분야·연도는 논문, 월별·용도는 문장)

  동작한다
- 화면 확인 항목: 편집·삭제·상태 전환·한줄평·검색이 그대로 되는지, 읽을 예정 섹션이
  남아 있는지, 필터를 걸었을 때 빈 논문이 사라지는지, 남의 페이지에서 조작 버튼만
  숨는지
- **공유 DB 에 쓰지 않는다.** 백필만 예외이고 그것도 승인 후에

# 주간 스터디 보고서 설계

작성일 2026-09-09

## 배경

스터디가 매주 어떻게 진행됐는지가 지금은 아무 데도 남지 않는다. 사이트에는
차시별 기록 화면(`/sessions/[id]`)이 있지만 "누가 무슨 논문을 올렸나" 수준이고,
불참 사유는 메신저로 주고받다가 사라진다.

보고서를 한 장 만들면 그 주의 스터디가 기록으로 남는다. 그리고 보고서가 채워지려면
각자 기록을 남길 수밖에 없으므로, 보고서는 산출물이면서 동시에 기록을 유도하는 장치다.

다만 **사이트가 규칙을 강제하지는 않는다.** "좋은 문장 1개 이상 수집"은 스터디원끼리의
약속이고, 사이트는 안 지킨 자리를 `기록 전`으로 비워 보일 뿐이다. 저장을 막거나
경고하는 기능은 넣지 않는다 — 넣었을 때 얻는 것보다 잃는 것이 많다.

## 범위

**이 스펙에 포함**

- 차시별 주간 보고서 페이지
- 불참 선언과 사유
- 하이라이트에 "수집 용도" 라벨 (= 수집한 문장 표시)
- 논문 등록 진입점을 차시 쪽으로 이전
- 링크로 arXiv 메타데이터 자동 채움

**이 스펙에서 제외**

- 개인 논문 기록 아카이브(멤버 탭 개편, 집계·시각화, LLM 분석) — 별도 스펙.
  이 스펙이 만드는 `papers.category`, `papers.published_year`, `highlights.purpose`가
  그 기능의 재료가 된다.
- 기록을 강제하는 장치 일체
- 로그인·권한의 실제 강제 (지금처럼 UI 수준 차단 유지)

## 데이터 모델

기존 테이블에 컬럼만 더한다. 새 테이블도, 삭제도, 이름 변경도 없다.

### `papers` — arXiv 메타데이터

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `category` | `text default ''` | arXiv 분류 코드 (`cs.CL`). arXiv가 아니면 빈 값 |
| `published_year` | `int` | 논문 발행연도. 모르면 `null` |

분류 코드를 사람이 읽는 이름(`cs.CL` → 자연어처리)으로 바꾸는 대응표는 코드에 둔다
(`lib/arxivCategories.ts`). DB에는 원본 코드만 저장한다 — 표현이 바뀌어도 데이터는 그대로다.

`published_year`는 **논문 발행연도**다. 읽은 시기는 이미 `read_date`에 있고 차시 날짜와
겹치므로 따로 두지 않는다.

### `session_attendees` — 불참 선언

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `status` | `text not null default 'present'` | `present` \| `absent` |
| `reason` | `text default ''` | 불참 사유. 참석이면 빈 값 |

지금은 행이 있으면 참석, 없으면 아무것도 모르는 상태다. 여기에 상태를 붙이면 불참을
명시적으로 선언할 수 있고, 행이 없으면 여전히 "아직 응답 없음"이다.

기존 행은 모두 참석이었으므로 기본값 `present`가 그대로 맞는다.

테이블 이름이 이제 참석만 담지 않지만, 이름을 바꾸면 기존 코드와 마이그레이션 파일이
함께 흔들리므로 그대로 둔다.

### `highlights` — 수집 용도

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `purpose` | `text default ''` | 수집 용도. 빈 값이면 개인 하이라이트 |

**이 값이 있으면 "수집한 문장", 없으면 개인 하이라이트다.** 보고서에는 값이 있는 것만
올라간다. 기존 하이라이트는 전부 빈 값이므로 과거 기록이 엉뚱하게 분류되지 않는다.

용도 선택지는 코드에 상수로 둔다 (`lib/highlightPurposes.ts`):

- `좋은 표현`
- `문단 구조`
- `논리 연결`
- 기타 — 직접 입력한 문자열이 그대로 들어간다

앞의 셋은 README에 적힌 스터디 목적 그대로다. 자유 입력을 같은 컬럼에 담으므로 용도가
늘어나도 스키마는 그대로다.

기존 5색(`highlights.color`)과는 **별개**다. 색은 PDF 위의 시각 표시로 지금 의미를 그대로
유지하고, 용도는 분류 라벨이다. 하나에 두 의미를 얹으면 "노랑으로 칠하고 싶은데 분류는
논리 연결"인 순간 충돌한다.

### 마이그레이션

`supabase/add-report-2026-09-09.sql` — 기존 파일들과 같은 방식으로 몇 번을 다시 실행해도
안전하게 쓴다.

```sql
alter table papers add column if not exists category       text default '';
alter table papers add column if not exists published_year int;

alter table session_attendees add column if not exists status text not null default 'present';
alter table session_attendees add column if not exists reason text default '';
alter table session_attendees drop constraint if exists session_attendees_status_check;
alter table session_attendees add constraint session_attendees_status_check
  check (status in ('present', 'absent'));

alter table highlights add column if not exists purpose text default '';
```

`supabase/schema.sql`에도 같은 컬럼을 반영한다 (이 파일이 구조의 정본이다).

전부 컬럼 추가라 **기존 코드가 돌아가는 상태에서 먼저 실행해도 안전하다.**

## arXiv 메타데이터 자동 채움

### 왜 다시 넣는가

예전에 있던 자동 추출은 **PDF 본문에서 글자를 긁어내는** 방식이라 부정확해서 제거됐다
(커밋 `b21486b`, README에 기록). arXiv API는 추정이 아니라 **원본 메타데이터**를 내주므로
같은 문제가 없다.

그리고 이 데이터가 개인 아카이브의 분야별·연도별 집계에 그대로 필요하다.

### `/api/arxiv` 라우트

브라우저에서 arXiv를 직접 부르면 CORS에 막히므로, 기존 `/api/pdf`와 같은 방식으로 서버
라우트를 하나 둔다.

```
GET /api/arxiv?url=<논문 링크>
→ 200 { title, authors, published_year, category }
→ 422 { error }   arXiv 링크가 아니거나 메타데이터를 못 찾음
→ 502 { error }   arXiv 응답 실패
```

- 링크에서 arXiv id를 뽑는다. `arxiv.org/pdf/2402.08787`, `.../2402.08787v4`,
  `arxiv.org/abs/2402.08787` 세 형태를 받는다.
- `https://export.arxiv.org/api/query?id_list=<id>` 를 호출한다. 응답은 Atom XML이다.
- 필요한 필드는 `title`, `author/name`, `published`, `primary_category@term` 넷뿐이라
  정규식으로 뽑는다. XML 파서를 새로 의존성에 넣지 않는다. 형식이 바뀌어 파싱이 실패하면
  422로 떨어지고 사용자는 손으로 입력하면 되므로, 실패가 기능을 막지 않는다.
- `/api/pdf`와 같이 25초 타임아웃과 `AbortController`를 쓴다.

`authors`는 저자명을 `, `로 이어 붙인 문자열로 돌려준다 — `papers.authors`가 지금도
자유 문자열이라 구조를 바꾸지 않는다.

### 입력 흐름

1. 링크를 붙여넣으면 자동으로 조회한다 (입력이 멈춘 뒤 한 번, 디바운스)
2. 성공하면 제목·저자 칸이 채워지고 분야·연도가 함께 표시된다
3. **채워진 값은 그대로 고칠 수 있다.** 자동 채움은 편의지 잠금이 아니다
4. 실패하면 조용히 넘어가고 손으로 입력한다. 실패를 에러로 띄우지 않는다 —
   arXiv가 아닌 논문도 정상적인 경우다

## 진입점 이전

### 지금 무엇이 잘못됐나

논문 추가 폼이 멤버 페이지에 있고, **스터디 일정이 "선택 안 함"이 기본인 옵션 드롭다운**이다.
실제로는 차시에 참여하려고 논문을 고르는 것인데 차시가 곁다리로 붙어 있다.

### 바뀌는 모습

차시 카드에 버튼 하나를 둔다.

```
[ ＋ 이번 차시 기록 ]
   ├ 논문 등록 :  링크 → 제목·저자·분야·연도 자동 채움
   └ 불참      :  사유 입력
```

**두 곳에 같은 버튼을 둔다.**

- 홈의 예정 스터디 카드 — 다음 차시를 준비할 때
- 차시 상세 페이지 `/sessions/[id]` — 지난 차시를 나중에 채울 때

두 번째가 없으면 스터디가 끝난 뒤 문장 수집을 채워 넣을 자리가 사라진다. 예정 차시는
하나씩만 표시되기 때문이다. 실제로는 스터디를 하고 나서 기록을 채우는 경우가 더 많다.

**상태(`읽음` / `읽을 예정`)는 지금처럼 사용자가 고른다.** 차시 날짜로 자동 판정하지
않는다 — 읽을 예정이었는데 못 읽는 경우도 있고 다음 주에 이어서 읽는 경우도 있어서
날짜로는 맞힐 수 없다. `read_date`는 기존 동작 그대로다(`읽음`이면 차시 날짜, `읽을 예정`이면
비움).

없어지는 것은 "스터디 일정" 드롭다운 하나뿐이다.

### 멤버 페이지에서 빠지는 것

`＋ 논문 기록 추가` 폼을 **없앤다**. 등록은 차시 쪽 한 곳으로 모인다.

멤버 페이지는 읽어온 기록을 **보는** 곳으로 성격이 정리된다. 목록·편집·삭제·한줄평은
그대로 둔다.

## 불참 선언

`＋ 이번 차시 기록` → 불참을 고르면 사유를 입력받아 `session_attendees`에
`status='absent'`, `reason`으로 저장한다. 이미 행이 있으면 갱신한다.

**`absent`가 우선한다.** 보고서의 분류는 이렇다.

```
참석자    = (status='present' 인 사람 ∪ 그 차시에 논문을 등록한 사람) − (status='absent' 인 사람)
불참자    = status='absent' 인 사람
응답 없음 = 나머지 멤버 전원
```

그 차시에 논문을 등록해 둔 사람이 불참으로 바꾸면 논문은 개인 기록으로 남되 보고서에는
불참자로 나온다. 이 경우 저장 전에 "등록한 논문이 있습니다. 불참으로 바꿀까요?"로 한 번 묻는다.

불참을 되돌리는 것도 `＋ 이번 차시 기록`에서 한다. 이 폼은 열릴 때 **내 현재 상태를 먼저
보여주고**(응답 없음 / 참석 / 불참 + 사유) 거기서 바꾸게 한다. 예정 스터디 카드에는 기존
`참석` 버튼이 없어서(그 버튼은 최근 스터디와 차시 상세에만 있다) 폼 밖에서는 되돌릴 자리가
없기 때문이다.

최근 스터디와 차시 상세에 이미 있는 `참석` 버튼은 `status='present'`를 쓰도록 바꾼다.

## 보고서 페이지

**기존 `/sessions/[id]`를 보고서로 개편한다.** 새 경로를 만들지 않는다. 캘린더와 홈에서
이미 이 경로로 링크가 걸려 있고, 같은 정보를 두 페이지로 나눌 이유가 없다.

### 구성

참석자, 불참자, 응답 없음 세 갈래다. 참석과 불참이 본체이고, 응답 없음은 누가 아직
아무것도 안 남겼는지 보이도록 이름만 나열한다.

```
── 참석자 ──
이하늘
  읽은 논문    RETHINKING MACHINE UNLEARNING FOR LLMs
  한줄평       LLM unlearning 서베이부터 읽어봤는데…
  수집 문장    "…"  — 왜 골랐는지          [좋은 표현]
               "…"  — 왜 골랐는지          [논리 연결]
               "…"  — 왜 골랐는지          [문단 구조]
               [ 더보기 2개 ]

김민석
  읽은 논문    MacroHFT: Memory Augmented…
  한줄평       기록 전
  수집 문장    기록 전

── 불참자 ──
정승원       개인 일정

── 응답 없음 ──
김윤지 · 이거루 · 장윤영
```

- **`기록 전`은 항목별로 표시한다.** 사람을 통째로 "기록 전"으로 묶지 않는다. 논문은
  올렸는데 한줄평이 없으면 한줄평 자리만 비어 보인다.
- **수집 문장은 3개까지 펼치고 나머지는 더보기**로 접는다. 문장과 이유(메모)가 한 쌍으로
  나오고, 용도 라벨을 함께 보인다.
- **한 사람이 그 차시에 논문을 여러 편 올렸으면** 논문 줄이 여러 개가 되고, 수집 문장은
  각 논문 아래에 그 논문 것만 붙는다. 어느 문장이 어느 논문에서 나왔는지가 섞이지 않는다.
  더보기는 논문마다 따로 센다. 한줄평은 차시 단위라 사람당 한 번만 나온다.
- 한줄평은 선택이다. 안 썼으면 그 자리만 `기록 전`이 된다.
- **응답 없음**은 이름만 한 줄로 나열한다. 참석·불참 어느 쪽도 선언하지 않았고 논문도
  올리지 않은 멤버다. 지금 화면은 이런 사람을 아예 안 보여주는데, 보고서에서는 누가
  아직 안 남겼는지가 보이는 편이 낫다. 경고나 독촉 문구는 붙이지 않는다.
- 보고서를 보다가 자기 칸이 비어 있으면 같은 페이지의 `＋ 이번 차시 기록` 버튼으로
  바로 채운다.

### 수집 문장 조회

지금은 하이라이트를 논문 단위로만 조회한다(`fetchHighlights(paperId)`). 보고서는
**한 차시 × 전원**이 필요하므로 조회를 하나 추가한다.

```ts
fetchSessionHighlights(sessionId): Promise<Highlight[]>
// 그 차시에 등록된 논문들의 하이라이트 중 purpose 가 빈 값이 아닌 것
```

논문 id를 먼저 모으고 `in` 조건으로 한 번에 읽는다 — 논문마다 따로 조회하지 않는다.

개인 아카이브(별도 스펙)는 같은 데이터를 **한 사람 × 전 기간**으로 자른다. 두 조회가
`lib/db.ts`에 나란히 놓이는 형태가 된다.

## 수집 용도 입력

용도를 고르는 자리는 두 군데다. 둘 다 `components/PdfHighlighterView.tsx` 안이다.

- **새 하이라이트를 만들 때** — `NewHighlightTip`에 색 선택 옆으로 용도 선택을 붙인다
- **기존 하이라이트를 고칠 때** — 메모 패널의 수정 폼에 같은 선택을 붙인다

선택 UI는 `없음 / 좋은 표현 / 문단 구조 / 논리 연결 / 기타`이고, 기타를 고르면 자유 입력
칸이 열린다. 기본값은 `없음`이다 — 기록을 남기는 데 마찰을 더하지 않는다.

용도가 붙은 하이라이트는 메모 패널에서 라벨로 구분되어 보인다.

## 과거 기록

개편 전에 쌓인 기록이 어떻게 되는지.

**그대로 맞게 들어가는 것**

- `session_attendees`의 기존 행은 모두 "참석 체크한 사람"이므로 기본값 `present`가 정확히
  맞는다. 과거 참석 기록은 그대로 살아난다
- 한줄평은 건드리지 않는다. 과거 한줄평이 보고서에 그대로 나온다

**비어 있게 되는 것**

- **`highlights.purpose`가 전부 빈 값이다.** 어떤 하이라이트가 "좋다고 생각해 모은 문장"
  이었는지는 데이터에 없어서 자동으로 알 수 없다. 따라서 **과거 차시 보고서의 수집 문장
  칸은 대부분 `기록 전`이 된다.** 메모 패널의 수정 폼에서 기존 하이라이트에 용도를 달면
  그 시점부터 보고서에 나타난다 — 소급은 사람이 한다
- **과거 차시의 불참자는 데이터가 없다.** 메신저로만 오갔으므로 소급 불가다. 그 사람들은
  불참자가 아니라 "응답 없음"에 들어간다. 본인이 차시 상세에서 나중에 불참을 선언하면
  옮겨간다 (버튼이 지난 차시에도 있다)
- `papers.category`, `published_year`도 빈 값이지만 **이건 자동으로 채울 수 있다.**
  아래 백필 참고

**그대로 남는 것**

- 차시를 안 고르고 등록된 기존 논문(`session_id`가 `null`)은 멤버 페이지 목록에 계속
  보이고, 어느 차시 보고서에도 나오지 않는다. 지금과 같다. 다만 앞으로 차시 없는 논문을
  새로 등록할 방법은 없어진다 — 등록을 차시 한 곳으로 모으기로 한 결정의 결과다

**과거 차시의 "응답 없음"은 그대로 둔다**

과거 차시를 열면 응답 없음에 사람이 많이 뜬다. 실제로는 참석했는데 버튼을 안 눌렀거나,
불참이었는데 기록할 곳이 없었던 사람들이다. 여기에 날짜 분기를 넣어 감추거나 문구를
다르게 하지 않는다 — 스터디원이 서로 사정을 아는 규모이고, 날짜 분기는 앞으로 계속
신경 쓸 거리가 되기 때문이다. 소급 입력하면 어차피 채워진다.

**arXiv 메타데이터 백필**

`scripts/backfill-arxiv.mjs` — `pdf_url`이 arXiv인 기존 논문을 훑어 `category`와
`published_year`가 빈 것만 채운다. 한 번 돌리면 과거 논문도 분야별·연도별 집계에 들어간다.

- 이미 값이 있는 행은 건너뛴다 (몇 번을 돌려도 안전하다)
- arXiv에 대한 요청 사이에 간격을 둔다 (arXiv API 권고)
- 실패한 논문은 건너뛰고 목록으로 보고한다. 중간에 멈추지 않는다
- `/api/arxiv`와 같은 파싱 코드를 쓴다 — 두 벌로 갈라놓지 않는다

## 에러 처리

- **arXiv 조회 실패** — 조용히 넘어가고 손으로 입력한다. arXiv가 아닌 논문도 정상이므로
  에러로 띄우지 않는다
- **불참 저장 실패** — 지금 출석 체크와 같은 방식으로 낙관적 반영 후 실패하면 되돌리고
  메시지를 띄운다
- **마이그레이션 미실행** — `fetchAttendance`가 지금 그렇게 하듯, 새 컬럼 조회가 실패하면
  경고만 남기고 나머지 화면은 그대로 돈다

## 검증

- `npx tsc --noEmit`, `npm run lint`, `npm run build`
- 프로덕션 빌드(`next build && next start`)를 로컬에서 띄우고 실제 데이터로 확인한다.
  dev 모드는 StrictMode 이중 마운트 때문에 프로덕션과 다르게 동작한다 (PDF 뷰어에서
  이미 겪음)
- **공유 DB에 쓰지 않는다.** 읽기만으로 확인하고, 쓰기 흐름은 스터디원에게 보이지 않는
  방식으로 검증한다
- 확인 항목
  - 보고서: 참석자/불참자 분리, 항목별 `기록 전`, 수집 문장 3개 + 더보기
  - 불참 선언 후 보고서에 사유가 나오고 참석자에서 빠지는지
  - 논문을 등록한 사람이 불참으로 바꿀 때 확인을 묻는지
  - arXiv 링크로 제목·저자·분야·연도가 채워지는지, 채운 뒤 고칠 수 있는지
  - arXiv가 아닌 링크에서 에러 없이 손 입력으로 넘어가는지
  - 마이그레이션 전 코드로도 화면이 깨지지 않는지

## 이 스펙이 남기는 것

개인 아카이브(별도 스펙)가 쓸 재료가 이 작업으로 생긴다.

- `papers.category`, `papers.published_year` → 분야별·발행연도별 집계
- `highlights.purpose` → 용도별 수집 문장 리스트
- `fetchSessionHighlights`와 짝이 되는 멤버 기준 조회

수집이 규칙으로 자리잡아야 아카이브에서 볼 것이 쌓이므로 이 스펙이 먼저다.

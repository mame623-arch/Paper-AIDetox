# 논문 AI 디톡스 스터디

AI 없이 논문/글을 읽고, 좋은 표현·문단 구조·논리 연결을 직접 파악하기 위한 스터디용 웹앱.
스터디원 전원이 같은 vercel.app 링크에서 기록을 **공유**합니다.
UI는 레퍼런스(dami-safeagent)의 디자인 토큰(흰 배경 · `#f6f7f9` 사이드바 · `#2f6df6` 파랑 · Pretendard)을 그대로 따랐습니다.

## 기능 / 페이지

| 경로 | 설명 |
| --- | --- |
| `/` (홈) | **최근 스터디 + 예정 스터디** 2개를 표시. 최근 스터디는 **참석자 수 + 참석자 목록**과 **보고서 보기 →** 링크를 보여줍니다(**참석 = 논문 등록**입니다). 예정 스터디에는 **＋ 이번 차시 기록**(논문 등록 / 불참)이 붙습니다. 멤버 클릭 → 개인 페이지, 논문 클릭 → 해당 논문 페이지 |
| `/members` (멤버 목록) | 전체 멤버 카드. 클릭 시 개인 페이지로 |
| `/members/[id]` (개인 아카이브) | **기록** / **읽기 경향** 두 탭. **기록** 탭은 읽은 논문마다 **수집 문장**이 붙고, **용도 칩**(좋은 표현·문단 구조·논리 연결·기타)으로 걸러볼 수 있으며, 10편씩 **페이지네이션**됩니다. 오른쪽 레일에는 **분야·발행연도**(논문 수 기준) · **월별·용도**(문장 수 기준) 집계 차트 넷이 서는데, 월별은 **읽은 날짜** 기준이라 발행연도와는 다른 축입니다. **읽기 경향** 탭은 아직 준비 중 안내만 보여줍니다. 기존의 **편집(제목·저자·링크)·상태변경·삭제·검색·읽을 예정** 목록은 그대로입니다. 논문 **등록**은 여기서 하지 않고, 홈의 예정 스터디나 차시 상세의 **＋ 이번 차시 기록**에서 합니다 |
| `/members/[id]/papers/[paperId]` (세부 논문) | PDF 뷰어(**확대·축소**) + 문장/**영역** 하이라이트 + 메모(**수정 가능**). 하이라이트는 **5가지 색**으로 구분하고, 따로 **수집 용도**(좋은 표현·문단 구조·논리 연결·기타)를 고르면 그 문장이 주간 보고서에 올라갑니다. 오른쪽 메모 패널은 **토글**됩니다. 멤버 페이지·홈·차시 보고서의 논문 제목 링크로 진입 |
| `/calendar` (캘린더) | 월 달력 + 일정(날짜·시간·장소·제목) 추가/삭제 → 홈의 최근/예정 스터디에 반영 |
| `/sessions/[id]` (차시 보고서) | 그 차시의 **주간 보고서**. 멤버를 **참석자 / 불참자 / 응답 없음**으로 나누고, 참석자마다 **읽은 논문 · 한줄평 · 수집 문장**을 항목별로 보여줍니다(빈 항목은 각각 `기록 전`). 같은 자리의 **＋ 이번 차시 기록**으로 그 차시의 참석/논문 등록/불참을 기록·수정합니다 — 지난 차시를 나중에 채우는 자리이기도 합니다. 캘린더의 일정을 클릭해 진입 |
| `/api/pdf` | 외부 PDF를 동일 출처로 스트리밍하는 프록시 (pdf.js CORS 우회) |
| `/api/arxiv` | arXiv 링크의 메타데이터(제목·저자·분야·발행연도)를 가져오는 프록시. 논문 등록 폼이 내부적으로 호출합니다 |

> 제목·저자는 기본적으로 **직접 입력**합니다. arXiv 링크를 넣으면 자동으로 채워지는데,
> 이는 PDF 본문에서 긁어오던 예전 자동 추출 기능과는 다른 방식입니다 — 자세한 내용은
> 아래 "기술 스택" 다음 문단을 참고하세요. 등록 후에도 언제든 **편집**으로 제목·저자·
> 링크를 고칠 수 있습니다.
> 왼쪽 사이드바는 « / » 버튼으로 접었다 펼 수 있습니다(선택은 브라우저에 저장).

## 기술 스택

- **Next.js 14 (App Router) + TypeScript** — 실제 URL 라우팅, Vercel 네이티브
- **Tailwind CSS** — 사이드바 + 카드 기반의 차분한 UI
- **Supabase** — 공유 DB(멤버/세션/논문/하이라이트/한줄평/출석)
- **react-pdf-highlighter** (pdfjs-dist) — PDF 뷰어 + 하이라이트 + 메모

> 논문을 등록할 때 arXiv 링크를 넣으면 제목·저자·분야·발행연도가 자동으로 채워집니다.
> 예전에 있던 PDF 본문 추출과 달리 arXiv 가 내주는 원본 메타데이터라 정확합니다.
> arXiv 가 아닌 링크는 직접 입력합니다.

## 1. Supabase 설정

1. <https://supabase.com> 에서 프로젝트를 1개 생성합니다.
2. 대시보드 좌측 **SQL Editor** → New query 에 **`supabase/schema.sql`** 를 붙여넣고 **Run**
   (members/sessions/papers/highlights/reviews/session_attendees + 공개 정책 생성.
   언제 다시 실행해도 안전하며 데이터는 지워지지 않습니다).
3. 이어서 **`supabase/seed.sql`** 을 **Run** — 실제 멤버 10명(김민석·김민준·김윤지·이거루·
   이윤석·이하늘·장윤영·정승원·정승현·정지우)과 예시 일정/논문을 채웁니다.
   - ⚠️ seed.sql 은 기존 데이터를 비우고 다시 채우므로 **초기 1회/초기화 시에만** 실행하세요.
4. **이미 쓰고 있던 DB라면** `supabase/schema.sql` 을 다시 Run 하는 게 가장 간단합니다
   (2번의 테이블 위에 새 컬럼만 보태며, 아래 두 마이그레이션 내용을 전부 포함합니다).
   필요한 부분만 좁히려면 **날짜 순서대로** Run 하세요 — 먼저 출석 표 자체를 만드는
   **`supabase/add-attendance-2026-09-03.sql`**, 그 다음 그 표에 컬럼을 보태는
   **`supabase/add-report-2026-09-09.sql`**(논문 분야·발행연도, 출석 사유, 하이라이트
   수집 용도) — 순서를 바꾸면 후자가 아직 없는 표를 고치려다 실패합니다. 이미
   `schema.sql` 로 출석 표가 있다면 `add-report-2026-09-09.sql` 만 이어서 Run 하면
   됩니다. 모두 기존 데이터를 지우지 않는 멱등 스크립트입니다. 출석 표가 있어야
   출석 기록이, 보고서용 컬럼이 있어야 차시 상세의 **주간 보고서**(불참
   사유·수집 문장 포함)가 동작합니다.
5. 대시보드 **Project Settings → API** 에서 다음 두 값을 복사합니다.
   - `Project URL`
   - `anon` `public` key

### 기존 논문 arXiv 메타데이터 백필 (선택)

`category`(분야)·`published_year`(발행연도) 컬럼은 나중에 추가돼서, 그 전에
등록한 논문에는 비어 있을 수 있습니다 — 그러면 개인 아카이브의 분야·발행연도
차트가 비어 보입니다. `scripts/backfill-arxiv.mjs` 로 한 번에 채웁니다.
**이 스크립트는 스터디원 전체가 함께 쓰는 운영 Supabase DB 에 직접 씁니다
(PATCH)** — 돌리기 전에 스터디원과 시점을 맞추세요. **몇 번을 다시 돌려도
안전**하며, **이미 값이 있는 필드는 그대로 두고 비어 있는 필드만** 채웁니다.
PDF 링크가 없는 논문은 애초에 대상에서 빠지고,
링크는 있지만 arXiv 링크가 아닌 논문은 시도 후 실패 목록으로 남습니다(둘 다
DB 는 건드리지 않습니다). 파싱 코드를 따로 두지 않고 실행 중인 앱의
`/api/arxiv` 를 그대로 부르므로, 앱을 띄운 채로 돌립니다.

```bash
npm run build && npx next start -p 3200 &
BASE=http://localhost:3200 node scripts/backfill-arxiv.mjs
```

`.env.local` 의 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` 를
그대로 읽으므로 별도 설정은 필요 없습니다.

## 2. 로컬 실행

```bash
# 1) 환경변수 파일 생성
cp .env.example .env.local
#    .env.local 에 위에서 복사한 두 값을 붙여넣기
#    NEXT_PUBLIC_SUPABASE_URL=...
#    NEXT_PUBLIC_SUPABASE_ANON_KEY=...

# 2) 의존성 설치 & 실행
npm install
npm run dev
```

브라우저에서 <http://localhost:3000> 접속.
키가 없으면 상단에 "Supabase 미설정" 안내가 표시됩니다.
테스트는 `npm test` (vitest) 로 순수 로직 모듈(arXiv 파싱·보고서 참석 분류 등)의
유닛 테스트를 돌립니다.

### 사용법

1. **왼쪽 사이드바 "나"** 에서 본인 이름을 고릅니다 (localStorage 저장).
   사이드바가 거슬리면 **«** 로 접고, 왼쪽 끝 **»** 로 다시 폅니다.
2. 홈의 **예정 스터디** 카드(또는 캘린더를 거쳐 들어간 그 차시의 상세 페이지)에서
   **＋ 이번 차시 기록**을 열고 **참석 / 논문 등록 / 불참** 중 하나를 고릅니다.
   - **논문 등록**: PDF 링크에 **arXiv 링크**를 붙이면 제목·저자·분야·발행연도가
     자동으로 채워집니다(이미 채워 둔 칸은 그대로 두고 빈 칸만 채웁니다).
     arXiv 가 아닌 링크는 **제목**(필수) · 저자를 직접 입력합니다.
   - **불참**: 사유를 적어 둘 수 있습니다(생략 가능). 마음이 바뀌면 같은 자리를
     다시 열어 **참석**이나 **논문 등록**으로 바꿀 수 있습니다.
   - 지난 차시에 놓친 기록은 그 차시 상세 페이지(=주간 보고서)에서 같은
     **＋ 이번 차시 기록**으로 나중에 채웁니다.
   - 이미 등록한 논문의 제목·저자·링크를 고치려면 멤버 페이지 목록의 **편집**을 씁니다.
3. 논문을 클릭 → PDF 뷰어에서 **문장을 드래그** → **색 선택 + 용도 선택 + 메모** → 저장.
   - **수집 용도**(좋은 표현 · 문단 구조 · 논리 연결 · 기타)를 고르면 그 문장이
     주간 보고서의 "수집 문장"에 올라갑니다. 기본값은 **없음**이며, 용도를 고르지
     않은 하이라이트는 개인 기록으로만 남습니다. 하이라이트 색과는 별개입니다.
   - 그림·표 같은 **영역**은 왼쪽 위 **□ 영역 선택** 을 켜고 드래그(또는 **Alt + 드래그**).
   - 왼쪽 위 **− 100% ＋** 로 확대·축소합니다(40%~400%). 가운데 %를 누르면 너비에 맞춥니다.
   - 상단 **메모** 버튼으로 오른쪽 패널을 열고 닫습니다(작은 화면은 기본으로 닫힘).
   - 패널에서 하이라이트를 클릭하면 해당 위치로 스크롤되고,
     **메모 수정**(또는 색 점)으로 메모 내용·색·용도를 나중에 고칩니다.
4. **캘린더**에서 일정을 추가하면 홈의 최근/예정 스터디에 자동 반영됩니다.
   시간·장소·제목은 `14:00–16:00` / `신공학관 5159` / `논문 디톡스 N차시` 가 기본값으로 채워집니다.
5. 홈 **최근 스터디**에서 참석을 확인합니다. 그 차시에 논문을 등록했으면 자동으로 참석,
   논문 없이 왔으면 **참석** 을 눌러 체크합니다.

## 3. Vercel 배포 (GitHub 연동)

```bash
# GitHub 새 repo 생성 후
git add -A
git commit -m "feat: AI 디톡스 스터디 웹앱"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

1. <https://vercel.com/new> 에서 위 GitHub repo를 **Import**.
2. **Environment Variables** 에 `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY` 두 개를 등록.
3. **Deploy** → 이후 `main` 에 push할 때마다 자동 재배포됩니다.

배포되면 `https://<프로젝트>.vercel.app` 링크를 스터디원과 공유하면 됩니다.

## 참고 / 한계

- 식별은 비밀번호 없는 **이름 선택** 방식입니다(소규모 신뢰 그룹 기준).
  추후 PIN/Auth로 강화하려면 `supabase/schema.sql` 의 RLS 정책을 좁히세요.
- 한줄평·메모 입력창은 **Enter 저장 · Shift+Enter 줄바꿈** 입니다(한글 조합 중 Enter는 무시).
- PDF는 **외부 링크 입력** 방식이며, 일부 사이트는 임베드를 제한할 수 있습니다.
  대부분의 arXiv PDF(`https://arxiv.org/pdf/<id>`)는 정상 동작합니다.
